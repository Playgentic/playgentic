Architecture: repo setup

Beyond the tests, a scaffolded suite ships the guardrails that keep an agent-written codebase honest: pre-commit gates, linting/formatting, the MCP wiring the pipeline needs, and CI. Here's what each piece is and how it fits — all of it yours to edit.

What's in the repo

my-suite/
  .husky/
    pre-commit              # lint-staged + step-docstring lint
    commit-msg             # commit message checks
  .lintstagedrc.json       # which linters run on staged files
  eslint.config.mjs        # flat-config eslint + typescript-eslint
  .prettierrc.json         # formatting rules
  .prettierignore
  .mcp.json                # playwright-test MCP server wiring
  .github/
    workflows/ci.yml       # typecheck / lint / format check
    workflows/codeql.yml   # static analysis
    workflows/gitleaks.yml # secret scanning
    gitleaks.toml
    dependabot.yml         # dependency updates
    pull_request_template.md
  .vscode/
    settings.json          # format-on-save, etc.
    extensions.json        # recommended extensions

Pre-commit gates (husky + lint-staged)

The pre-commit hook is the local quality gate. It runs lint-staged (eslint + prettier on the files you're committing) and npm run lint:steps (the step-docstring gate). A commit with an undocumented step, a lint error, or a formatting miss is blocked before it lands.

The commit-msg hook validates the commit message. Together they mean the agents' output has to clear the same bar as hand-written code before it enters history.

Why this matters for agentic work The docstring gate is what keeps the step wiki accurate — and the wiki is what lets the orchestrator reuse steps instead of duplicating them. The pre-commit hook is load-bearing for the whole reuse-before-writing principle.

Linting & formatting

  • ESLint (eslint.config.mjs) — a flat config with typescript-eslint. Run it with npm run lint.
  • Prettier (.prettierrc.json) — npm run format to write, npm run format:check in CI.
  • TypeScript — npm run typecheck (tsc --noEmit); also run inside agent:promote so a promotion aborts on a type error.

The playwright-test MCP

.mcp.json wires the playwright-test MCP server (via npx playwright run-test-mcp-server). This is the only thing that drives a real browser, and only the bdd-explorer subagent talks to it. Without this server the agent pipeline can't explore the app — everything else (scaffolding, linting, promotion) works without it.

CI & supply chain

  • ci.yml — typecheck, lint, and format-check on every push/PR. (Add the browser install + npm test here when you want the suite to run in CI.)
  • codeql.yml — GitHub CodeQL static analysis.
  • gitleaks.yml + gitleaks.toml — secret scanning, a backstop for the "creds live in .env, never in the repo" rule from Working off the template.
  • dependabot.yml — automated dependency-update PRs.
  • pull_request_template.md — a consistent PR checklist.

Editor config

.vscode/settings.json and extensions.json set format-on-save and recommend the relevant extensions, so a new contributor (or you on a new machine) gets consistent behavior immediately.

It's all yours Unlike the .claude/ agent definitions (managed by playgentic sync), everything on this page is ordinary project config the scaffold drops in once. Edit it freely — sync won't touch it.
